## Architecture

Deploy the Next.js website separately from the speech process. The website proxies submissions and polling to a persistent CPU FastAPI service. Model inference runs in one background worker. Do not spawn a model for every HTTP request.

Use a single API process for this starter. SQLite stores job metadata, and the in-process worker uses one loaded language model. Completed and failed records expire after an hour when new submissions arrive. Uploaded audio is deleted after processing, including failed jobs.

## Container

From the repository root:

```bash
docker build -f apps/api/Dockerfile -t natlaskit-api .
docker run --rm -p 127.0.0.1:8000:8000   -e HF_TOKEN -e NATLAS_API_KEY   -v natlaskit-models:/home/speech/.cache/huggingface   natlaskit-api
```

Export the two variables in the launching shell first. The Docker image includes FFmpeg and CPU PyTorch. A persistent model-cache volume avoids repeated downloads.

## Website

```bash
pnpm build
pnpm --filter @natlaskit/web start
```

Configure `NATLAS_API_URL` and `NATLAS_API_KEY` in the server environment. Never use public browser environment variables for credentials.

## Limits

The starter accepts 10 MB uploads and 30-second recordings, queues at most 16 pending or running jobs, and processes one at a time. CPU latency and memory must be measured on the intended host. Warm and cold timings should be reported separately.

For a publicly accessible playground, add gateway rate limits and abuse controls. For multi-instance operation, replace the in-process worker and SQLite queue with shared job storage and a durable worker queue.
